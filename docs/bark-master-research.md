# Bark master: features worth incorporating

Research snapshot from **2026-10-07**, before implementation. The baseline below records the dependency and master revisions at that point.

Implementation update: richer balances and wallet diagnostics are now exposed by `offchainBalance()` and `debugInfo()`, and [the dependencies](../bark-cpp/Cargo.toml) pin master commit `8661f24e902698047f32481545672b5cefd7b9cc`. The other optional API additions below remain follow-ups.

## Useful additions and enhancements

1. **More accurate balances — highest priority.** Three new categories explain previously misleading balances: `needs_refresh`, `pending_arkoor_send`, and `pending_offboard`. Expired VTXOs and those at the server's exit-depth limit move out of `spendable`; ongoing sends and offboards remain visible. `Balance::summary()` returns spendable, needs-refresh, pending, and total, with corresponding aggregation helpers. Round balance now measures locked inputs; incoming Lightning balance only counts after revealing the preimage. Extend our existing `offchainBalance()` result with the new fields and summary amounts. These are all satoshi integers. [Upstream balance change](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bark/2509), [library implementation](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/balance.rs).

2. **Choose Lightning retry duration.** `LightningSendOptions` adds `retry_for: Option<Duration>` alongside `wait`. New `_with` methods cover invoice, offer, Lightning address, LNURL, and custom-origin payments. Zero requests one attempt; the server caps longer values at its configured maximum. Existing methods retain their signatures and defaults. Add optional retry seconds to our payment methods, including invoice-with-origin. This controls server payment attempts; `wait` separately controls whether the API call waits. Requires server support. [Wallet options](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/lightning/pay.rs), [server behavior](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/server/2580).

3. **Emergency-exit estimate with a safety margin.** Estimation now prices transaction weights independently of the onchain wallet's coins, enabling an estimate before funding the exit. A new optional `fee_margin` scales the broadcast portion, defaulting to **1.2**. Already-confirmed transactions and sufficiently funded mempool packages avoid redundant charges. Enhance our existing estimate method with this option; treat the result as a funding target rather than an affordability guarantee. [Estimate change and removals](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bark/2511), [implementation](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/exit/estimate.rs).

4. **Swept exits become an explicit terminal outcome.** `ExitState::VtxoSwept` and `ExitError::VtxoSwept` identify an exit chain whose required inputs were spent onchain, including a server sweep during an expired VTXO's exit. The state includes `spent_inputs`, convertible to outpoint strings. Extend our existing detailed exit responses so the UI can explain why progression stopped; a refresh may still succeed. [New state](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/exit/models/mod.rs), [state details](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/exit/models/states.rs).

5. **Recovery of delegated refreshes and better seed recovery.** A wallet recreated from its seed can reconstruct delegated-round outputs completed while its database was absent. Recovery also scans both the regular and recovery mailboxes and checks server state. However, our wrapper calls `Wallet::create` separately before `Wallet::open`, so Bark's open-time `created_now` recovery branch does not run; we also provide no recovery callback. Delegated completion messages can recover through mailbox sync, but full seed recovery needs deliberate creation/open wiring and a surfaced recovery outcome. The recovery callback already existed in 0.7.1. [Delegated recovery](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bark/2536), [recovery scan](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/recovery.rs), [open logic](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/lib.rs), [local creation](../bark-cpp/src/utils.rs), [local opening](../bark-cpp/src/lib.rs).

6. **Public wallet diagnostics.** `Wallet::debug_info()` returns network, mailbox ID, and VTXO xpub; `Wallet::vtxo_xpub()` is independently public. This supports a small support-information API, converting all three values to strings. Our bindings currently expose neither. [Library accessors](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/lib.rs), [diagnostics addition](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bark/2578).

## Improvements inherited through existing operations

Refresh registration delays input locking until the round starts. Pending refreshes shrink or redelegate when another operation consumes inputs, reducing stranded locks after interruption. Existing maintenance/sync operations benefit once updated. Arkoor sends also fix input lookup when change is present. [Round changes](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bark/2443), [Arkoor fix](https://gitlab.com/ark-bitcoin/bark/-/commit/f74bab54).

Onchain sends, send-many, and drains now persist their signed transaction before broadcasting. A failed broadcast logs a warning and still returns the transaction ID; sync retries it. Our wrapper disables Bark's daemon, so callers must keep driving `onchainSync()` and avoid interpreting a returned transaction ID as accepted broadcast. [Broadcast behavior change](https://gitlab.com/ark-bitcoin/bark/-/commit/bcec0424).

## Required migration work

- **Height conversions:** `BlockHeight` and `BlockDelta` replace integer aliases. Convert explicitly across FFI/config/exit structures. `get_expiring_vtxos` now takes `BlockDelta`; `round_tx_required_confirmations` is also a delta backed by `u16`, requiring bounded conversion from our `u32`. JavaScript can keep number fields. [Newtypes](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bitcoin-ext/2499), [config types](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/bark/src/config.rs).
- **Balance conversion:** `pending_exit` changes from `Option<Amount>` to `Amount`, invalidating our `map_or` conversion. Add the three new categories to avoid missing funds. [Local conversion](../bark-cpp/src/cxx.rs), [upstream change](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bark/2509).
- **Exit contract:** estimation gains an argument and loses `fundable`; update Rust/CXX/C++/TypeScript together. `Exit::try_pending_total` is removed, so our `pending_exit_total()` wrapper also needs updating. Handle `VtxoSwept` in exhaustive state matches and expose its input details. `RoundFlowState` also adds `Redelegating` wherever matched exhaustively. [Local exit wrapper](../bark-cpp/src/exit.rs), [local state matches](../bark-cpp/src/utils.rs), and the upstream exit/round references above.

The library manifests retain the existing Rust editions and BDK dependency versions; upstream's lockfile updates Rust TLS dependencies. Rebuild and regenerate platform artifacts after the actual upgrade. The new embedded `bark-web` UI belongs to `barkd`, not our native library integration. [Dependency changes](https://gitlab.com/ark-bitcoin/bark/-/compare/bark-0.7.1...2c5f0fcbc198deb507d991535b2b509cf9607aa8), [web packaging](https://gitlab.com/ark-bitcoin/bark/-/blob/2c5f0fcbc198deb507d991535b2b509cf9607aa8/CHANGELOG/unreleased/bark-rest/2221).

BOLT12 sending, fee-estimation APIs, notifications, and detailed exits are already exposed here; they should not be presented as new additions. Recommendation: migrate balances and exit contracts first, add retry-duration options and diagnostics next, then explicitly integrate seed-recovery behavior. [Current public API](../react-native-nitro-ark/src/NitroArk.nitro.ts).
